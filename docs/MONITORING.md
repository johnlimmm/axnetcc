# 독립 운영 모니터링 콘솔

응답 서비스와 모니터링 콘솔은 서로 다른 웹 서버입니다. Grafana와 같은 운영용 콘솔의 형태이며, Grafana 제품 자체를 설치한 것은 아닙니다.

```text
사용자 브라우저 → 응답 서비스 (:3100) → Edge / Ollama
                      │
                /api/telemetry  ←  독립 수집기 (:3200)
                                       │  5초 주기
                                  별도 SQLite
                                       │
                                운영 콘솔 브라우저
```

## 실행

Node.js 22.13 이상이 필요합니다. `node:sqlite`와 TypeScript type stripping을 사용하며 별도 DB 서버나 새 npm 의존성은 필요하지 않습니다.

서비스 터미널:

```powershell
pnpm run build
pnpm exec vinext start --port 3100
```

모니터링 터미널:

```powershell
pnpm run monitor
```

- 응답 서비스: `http://localhost:3100` — 요청, 생성된 답변, 근거, 사용자 피드백.
- 운영 콘솔: `http://localhost:3200` — 시계열 성능, 실행 기록, 고정 벤치마크, 구현 현황, 수집된 사용자 피드백.
- 서비스의 이전 `/evaluation`, `/about` 주소는 독립 콘솔로 이동합니다. 서비스 메뉴에는 운영 콘솔 항목을 두지 않습니다.
- 콘솔은 기본적으로 `127.0.0.1`에만 바인딩합니다. 다른 기기에 공개하려면 인증을 적용한 별도 reverse proxy 구성이 필요합니다.

이미 서비스가 3000번 등 다른 포트에서 실행 중이면 수집원만 지정합니다.

```powershell
$env:MONITOR_SERVICE_URL = 'http://127.0.0.1:3000'
pnpm run monitor
```

## 실제 수집 동작

1. 비동기 `/api/runs`, 동기 `/api/orchestrate`, streaming API가 공유하는 오케스트레이션 경로에서 상태와 수치를 기록합니다.
2. `/api/telemetry`는 실행 ID, 시각, 상태, 수치 및 허용된 Agent·모델 식별자만 제공합니다. 요청·답변 본문, 프롬프트, 근거 문서, 내부 endpoint, 상세 오류 문자열은 내보내지 않습니다.
3. 수집기는 5초마다 변경된 실행을 조회하고 별도 `.local-monitor/telemetry.sqlite`에 upsert합니다. 실행별 revision으로 중복 수집과 중복 집계를 방지합니다.
4. 로컬 Agent 연결과 scheduler 상태는 최대 30초 간격으로 별도 확인합니다. 원격 Edge의 health 값은 기존 API가 제공하는 **설정 유효성**이며 실제 연결 확인으로 표시하지 않습니다.
5. 브라우저를 닫거나 ‘화면 자동 갱신’을 꺼도 수집기는 계속 동작합니다. 모니터링 **서버 프로세스**를 종료하면 수집은 멈춥니다.

## 콘솔에서 보는 지표

- 기간: 최근 15분·1시간·6시간·24시간·7일·30일.
- 필터: 실행 방식 및 최종 생성 backend. Agent별 fallback은 별도 집계.
- E2E P50/P95, 평균 TTFT·TPOT, 실행별 대기·추론 시간.
- 종료 처리량, 실패·일부 실패 비율, 취소 및 관측 중단 건수.
- Agent별 호출 수·지연 백분위, 연결 상태, 대기 작업 수, 최장 대기.
- 실행별 토큰·호출·전송 바이트·Privacy Risk v2 S/A/O·품질·인용 지표와 provenance.
- 최근 최대 200개 실행 조회 및 CSV 내보내기. CSV에도 요청·답변 본문은 포함하지 않습니다.
- 고정 벤치마크는 기존 v2 JSON에서 읽으며 운영 시계열에 합산하지 않습니다.
- 구현 현황은 수동 관리 문서 목록임을 표시하며 자동 배포·테스트 결과로 표현하지 않습니다.

### 집계 정의

P50/P95는 지연 계측값이 존재하는 완료·일부 실패 실행의 nearest-rank 백분위입니다. 표본 수를 함께 표시하며, 미측정 값은 0으로 채우지 않습니다. TTFT·TPOT는 기존 참여 모델 계측의 실행별 집계값이며 브라우저 첫 글자 출력 시간과 다릅니다.

처리량은 수집된 종료 건수 ÷ 선택 기간(분)입니다. 오류율은 `(실패 + 일부 실패) / (완료 + 일부 실패 + 실패 + 취소)`입니다. 서비스 재시작 때문에 완료 여부를 모르는 실행은 `interrupted`로 표시하고 오류율 분모에서 제외합니다. 이는 수집된 표본의 지표이지 시스템 전체의 완전한 SLA 통계가 아닙니다.

## 저장·재시작·수집 공백

- SQLite 기본 보관 기간은 30일이며 실행 ID와 서비스 instance ID를 복합 키로 사용합니다. 수집기 재시작 후에도 실행과 수집 cursor가 유지됩니다.
- 서비스 지표 버퍼는 메모리 기반입니다. 완료 후 최대 24시간·10,000건을 보관하며, 살아 있는 버퍼는 재연결 때 회수합니다.
- 수집 전에 서비스가 종료되거나 버퍼에서 제거된 실행은 복구할 수 없습니다. 버퍼 누락을 발견하면 경고를 표시합니다. 서비스 instance 변경은 별도 재시작 이벤트로 기록합니다.
- 서비스 장애 시 기존 SQLite 기록은 유지하고 현재 Agent·작업 상태는 ‘미확인’으로 표시합니다. 장애를 성공이나 0ms로 기록하지 않습니다.
- 프로토타입의 단일 Core·단일 수집기 범위입니다. 다중 Core 수집 및 중앙 저장소 HA는 포함하지 않습니다.

## 설정

| 환경 변수 | 위치 | 기본값 / 의미 |
| --- | --- | --- |
| `MONITOR_SERVICE_URL` | 콘솔 프로세스 | `http://127.0.0.1:3100` |
| `MONITOR_PORT` | 콘솔 프로세스 | `3200` |
| `MONITOR_INTERVAL_MS` | 콘솔 프로세스 | `5000`, 최소 1000 |
| `MONITOR_RETENTION_DAYS` | 콘솔 프로세스 | `30`, 1~365 |
| `MONITOR_DATABASE` | 콘솔 프로세스 | `.local-monitor/telemetry.sqlite` |
| `MONITOR_FEEDBACK_DIRECTORY` | 콘솔 프로세스 | 서비스의 Node 피드백 저장 경로. 미설정 시 `FEEDBACK_DIRECTORY` 또는 `.local-feedback` |
| `MONITOR_PUBLIC_URL` | 서비스 프로세스 | `http://localhost:3200`, 이전 URL 이동 대상 |
| `MONITOR_SCRAPE_TOKEN` | 서비스·콘솔 모두 | 선택 설정. 같은 값을 지정하면 telemetry 조회에 bearer 인증 적용 |

콘솔은 서비스의 `.env.local`을 자동으로 읽지 않습니다. 위 환경 변수를 콘솔 프로세스에 별도로 전달합니다. 원격 Cloudflare Core에서도 telemetry API를 노출할 수 있지만, SQLite 수집기는 Node 프로세스로 독립 실행해야 합니다. 스크레이프 토큰은 브라우저에 전달하지 않습니다.

## 피드백 조회와 서비스 화면

서비스의 `/feedback`과 결과 하단에서는 의견 작성과 접수 확인만 제공합니다. 서비스의 피드백 GET API는 405이며, 목록은 독립 콘솔의 `/feedback`에서 확인합니다. 콘솔 서버가 Node 피드백 파일 저장소를 직접 읽으므로 서비스와 같은 저장 경로를 지정해야 합니다. 원격 D1 피드백 조회 연동은 아직 지원하지 않습니다. 피드백 보관은 성능 SQLite의 30일 정책과 별개이며, 현재 자동 삭제하지 않습니다.

결과 화면은 통합 보고서 → 인용 근거 → Agent 선택 이유 순서입니다. 생성 중에는 실제 SSE·polling 상태에 따라 Core와 8개 Agent의 연결도가 갱신됩니다. 움직이는 연결선은 현재 처리 중인 연결이며, 운영 서버의 물리 네트워크 지도가 아닌 요청의 논리적 연결입니다.

Agent 선택 설명은 현재 `hybrid-profile-v1`의 실제 계산값을 사용합니다. 학습 임베딩이 아니라 요청 단어와 프로필 단어의 일치·포함·문자 bigram 유사도입니다. 프로필 점수는 평균 유사도 70% + 유사도 0.72 이상 토큰 비율 30%이며, 종합 점수에는 20% 가중치로 반영됩니다. 표시하는 단어별 기여도는 이 프로필 항목의 기여분입니다. 정책 우선 적용과 불확실성 보완 선택을 따로 표시하며, 보조 Agent 추가 당시의 미충족 필수 개념도 기록합니다. 요청 단어 추적은 서비스의 결과에만 포함되고 수치 전용 telemetry에는 포함하지 않습니다.
