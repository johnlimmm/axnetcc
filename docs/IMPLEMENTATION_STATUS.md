2026-09-08 기준. 연구용 분산 Multi-Agent RAG 프로토타입입니다.

- 기술·데이터·보안·법률·정책·재무·조달·운영의 8개 전문 Agent.
- Boundary Router v2: 주관 Agent, 필수 검토자, 근거 부족 시 지원 Agent 추가.
- Agent별 Edge RAG, 접근 정책, 민감 식별자 마스킹, 근거 ID 중심의 데이터 전달.
- Ollama 로컬 생성, 중앙 통합 보고서, Agent별 보고서와 인용 근거 조회. LLM 연결 실패 시 규칙 기반 대체 응답을 표시.
- 비동기 실행 API, 작업 대기열, SSE와 polling, 중단된 관측 재연결, 취소 및 실행 결과 조회.
- E2E·TTFT·TPOT, 대기·추론 시간, 호출·토큰·전송 바이트, Privacy Risk v2, 품질·인용·라우팅 진단.
- 파일럿·40문항·반복 평가 보고서. 버전과 실측/산출/추정/미측정 여부를 구분.

## 피드백 저장

서비스의 `POST /api/feedback`는 UUID 접수 번호, 선택적 실행 ID, 1~5점 별점, 개선 항목, 최대 2,000자의 의견을 받습니다. 서버 생성 시각과 함께 저장하며 요청 원문·응답 본문·연락처 입력란은 수집하지 않습니다. 기존 DLP 규칙으로 의견의 전화번호·이메일 등 알려진 식별자를 마스킹합니다. 의견은 운영자가 확인한다는 안내가 폼에 있습니다. 모든 개인정보를 식별하는 익명화 시스템은 아닙니다.

- 재시도는 동일 접수 번호와 동일 내용을 사용해 중복 집계하지 않습니다.
- 저장 실패는 HTTP 503으로 반환하고 성공으로 표시하지 않습니다. 입력을 유지한 채 재시도합니다.
- 서비스의 `GET /api/feedback`는 405를 반환합니다. 독립 콘솔의 `GET /api/feedback`에서만 전체 수, 평균 별점, 만족도 분포, 개선 항목별 수와 최근 의견을 반환합니다. 별점은 자동 품질 지표와 합산하지 않습니다.
- **Node 서버**: `.local-feedback/*.json`에 영속 저장합니다. 파일을 완전히 기록·동기화한 후 독점적으로 공개합니다. `FEEDBACK_DIRECTORY`로 영속 볼륨 경로를 설정할 수 있습니다. Git에서는 제외합니다.
- **Cloudflare/Vinext 개발 환경**: `FEEDBACK_DB` D1 바인딩을 사용합니다. 로컬 D1은 Wrangler 상태 디렉터리에 유지됩니다. 테이블은 최초 접근 시 생성합니다.
- **Cloudflare 원격 배포**: 실제 D1을 생성해 `FEEDBACK_DB`에 바인딩해야 합니다. 개발용 placeholder ID는 원격 DB가 아닙니다. 저장소가 없으면 503을 반환합니다. 이번 작업에서는 원격 DB 생성이나 배포를 수행하지 않습니다.

피드백 조회는 loopback에 바인딩된 독립 콘솔에서 제공합니다. 콘솔을 다른 기기에 공개하려면 운영자 인증 구성이 필요합니다. 별점은 인증된 사용자별 1회 투표를 보장하지 않습니다. 현재 콘솔은 Node 파일 저장소를 읽으며, 원격 D1 저장소 조회 연동은 포함하지 않습니다.

## 기록과 측정의 한계

서비스의 응답 레지스트리는 단일 프로세스 메모리이며 완료 후 약 30분, 최대 200개 실행을 유지합니다. 피드백과 독립 콘솔의 SQLite 지표는 별도로 저장됩니다. 응답이 만료되어도 수집된 성능 지표는 기본 30일 동안 조회·다운로드할 수 있습니다.

CSV에는 실행 ID, 방식, 완료 시각, 지표, 값, 단위, provenance만 포함합니다. 미측정은 빈칸, 측정된 0은 0으로 유지합니다. TTFT·TPOT는 실행에 참여한 모델 계측의 집계값이므로 브라우저에 첫 글자가 표시된 시간과 동일하다고 해석하지 않습니다.
