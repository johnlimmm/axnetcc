# Agent별 RAG 데이터 커버리지

- 알고리즘: BM25 sparse retrieval
- 공식·공개 문서: 26건
- 검색 청크: 3,027개
- 최종 갱신: 2026-07-30

하나의 공식 문서가 여러 전문영역에 해당하면 Agent별로 별도 청크를
생성한다. 따라서 합계는 원문을 단순 분할한 고유 청크 수가 아니라
전문영역별 검색 인덱스의 총 레코드 수다.

## 실제 RAG 처리

1. Router가 질의와 권한에 맞는 Agent를 선택한다.
2. 선택된 Agent가 자신의 `ragAgents` 범위에서 BM25 상위 근거를 검색한다.
3. 검색된 원문 일부와 근거 ID를 해당 Agent의 독립 로컬 LLM에 전달한다.
4. 응답과 함께 근거 ID, 원문 URL, 검색 점수를 반환한다.
5. 통합기는 관련성, 근거 내용 일치, 영역 커버리지, 완결성 및 인용 유효성을
   분리해 평가한다.

## 다음 데이터 확장 원칙

- 원문과 발행기관이 확인되는 공공기관 공식 자료를 우선한다.
- 문서별 발행일, URL, SHA-256, 라이선스 검토 상태를 저장한다.
- Agent별 최소 질의 세트와 정답 근거를 함께 만들어 데이터 양뿐 아니라
  검색 Recall@k, MRR, 근거 정확도를 측정한다.
- 중복 문서, 웹 메뉴·푸터 같은 잡음, 효력 종료 문서는 정제 또는 제외한다.
