# Grounded completion evaluator contract

This dependency-free runner measures **only the 40 first-pass answerable + 10 safety healthy-service cohort**, with three continuously occupied clients per cohort. It never claims complete distributed-demo acceptance. Fault/process-stop/cancellation/cold diagnostics, UI and independent final review remain separately required. No held-out questions or grades are shipped with runtime code.

```text
node scripts/evaluate-grounded-completion.mjs --manifest <manifest.json> --config <absolute-private-config.json> --output <new-directory>
node scripts/evaluate-grounded-completion.mjs --verify-report <directory/report.json> --grades <independent-grades.json>
```

Measurement exits nonzero because independent review is pending. Verification without grades, incomplete/failing cases, altered artifacts or unconfirmed cleanup also exits nonzero. A successful verification means the scoped Q1/Q2/Q3/P1 cohort passed, **not** full completion. Prior trial directories are never overwritten. Do not put private configs in the repository or output directory.

## Frozen manifest v1

- `schemaVersion: "grounded-completion/v1"`, `deploymentId`, `authorId`, `runtimeAuthorId` (different), ISO `frozenAt`, integer `seed`.
- Exact constants: `concurrency:3`, `deadlineMs:60000`, `watchdogMs:70000`, `maximumRequests:180`, `maximumWallMs:7200000`.
- `readiness:{policy:"admit-cold"|"delivered-readiness-barrier",description:string}`. The operator records actual initial residency, startup/readiness receipts and enforces the delivered readiness journey before running; this runner does not preload models or exclude first cases.
- `cases`: exactly 50 unique `{id,role,kind,query,rubricHash}`. Five `answerable` cases per functional role; six `mixed`, four `unsupported`. Rubrics are independent, sealed, source-grounded and never sent to the application. Their content validity is an independent reviewer responsibility, not inferred from this JSON schema.
- `workloadHash`: SHA256 of `JSON.stringify(cases)` (order preserved). Runtime execution order is sorted by SHA256 of `seed:caseId`, answerable cohort first, safety second; no repeat pooling.
- `rubricHash`: SHA256 of the sealed rubric file bytes; each case has its own canonical rubric hash.
- `configurationHash`: SHA256 of `JSON.stringify(config.frozenConfiguration)`. This binds operator-attested runtime settings, not credentials. Remote model/build identity still needs deployment receipts; local hashes alone cannot prove a remote process matches.
- `artifacts`: `{kind,path,sha256}` records for each of `build`, `corpus`, `prompts`, `models`, `configuration`, `rubrics`. Paths resolve relative to original manifest; hashes verify file bytes before any network call. Use exported immutable manifests/receipts for remote state. Rubric artifact hash must equal top-level `rubricHash`.

Private config requires `coreUrl`, `operatorToken`, `gatewayControlUrl`, `gatewayControlToken`, `inferenceControlUrl`, `inferenceControlToken`, `frozenConfiguration`; optional `telemetryToken`. HTTPS is required except loopback; URL credentials/query/fragment and redirects are forbidden. Existing dedicated controls are used only for final healthy restoration. Tokens must be at least 16 characters. Tokens are never written, and unexpected reflected token values are redacted from samples. Use only already authorized isolated demo endpoints; this is not a production fault tool.

## Artifacts and independent grade import

`manifest.json`, `samples.jsonl`, `report.json` retain exact case IDs, first occurrence, client monotonic timing, terminal status, full sequential SSE transcript, final result and distributed attempts/calls. Interrupted campaigns keep admitted rows and planned 40/10 denominators. Report binds both files by byte hash. No grades are generated by the runner and its measured data cannot self-certify quality.

Grade JSON:
- `schemaVersion:"grounded-grades/v1"`, `reviewType:"AI-assisted"`, distinct `graderId`/`adjudicatorId`, neither the `runtimeAuthorId`.
- Exact `workloadHash`, `rubricHash`, `samplesHash` bindings.
- Exactly 50 `cases`: `{id,rubricHash,F,C,U,safe,visibleClaimsSafe,reason,claims,adjudicated,adjudicationReason,disagreementResolved}`. Five decisions are booleans. `claims` is nonempty `{text,support:"supported"|"contradicted"|"unknown"|"no-answer",sourceSpans:[...]}`; supported claims require source-span references. Inspect all visible Agent/final assertions, not just final answers. F/C/U are the accepted independent semantic dimensions, not automated citation-ID matching.
- Every proposed failure must be adjudicated. Sort proposed passes by SHA256 of `seed:caseId`, adjudicate the first ceil(20%). `auditMissedUnsupportedClaim` is required; if true, adjudicate every proposed pass. All adjudicated entries require a reason and `disagreementResolved:true`; unresolved disagreement cannot pass. Reviewers must preserve initial findings/adjudication evidence externally, not rewrite failures away.
- Optional `evaluationInferenceCount` is separate external grading overhead; unknown remains null. Grades do not alter runtime counters.

The importer validates identities, dimensions, case/rubric/transcript bindings and audit coverage, **not semantic truth**. Independent source review remains essential.

## Safety and timing

Submission-to-final-body time includes queue/loading/retrieval/inference/failover. Polling adds up to 100ms, conservatively. SSE collection completes before timing ends; telemetry collection is excluded. Deadline is 60s, hard watchdog 70s. No-final/failed/deadline rows are +Infinity in conservative final-response P95; nearest rank retains these values. All-terminal P95 and fixed denominator are also reported. Fast refusals must fail U when answerable. Optional repeats cannot replace first attempts.

One admission latch spans all clients. Timeout, cancellation, missing telemetry or ambiguous failed physical inference immediately halts new work and aborts collection on peers; successful backup does not clear the latch. Active run IDs remain for bounded cancellation/collection, and dedicated faults restore in `finally`. No automatic resume. Transport drain or `/api/ps` is never backend-compute proof; inspect completion receipts or perform narrowly targeted owned-resource recovery before a **new preregistered** campaign. A run that stopped remains incomplete.

## Per-call usage API

`recordInferenceStage(requestId, stage, metrics, callId)`; `metrics.callId` also supported. Call IDs identify physical invocations, unique per run and stable when replayed. Stages: synthesis, supervisor, repair, verification, evaluation. Producer must create IDs before invocation and reuse on success/failure. First terminal observation per ID is idempotent; do not emit intermediate null then a different terminal event for the same ID.

Telemetry contains `calls`, derived `stages`, `usageByCategory` (agent/core/onlineVerification/evaluation), full/known totals and `callDetail`. Two calls 7/3 and 11/5 yield 18/8; an unknown call preserves 18/8 known subtotal but null full totals. Historical stage-only records have no invented per-call history (`legacy-stage-only`). Monitor normalization preserves IDs; `distributedCallsCsv` exports calls separately from physical Agent attempt body-byte CSV. Existing raw run JSON also contains calls. Prepared request bytes are not sent/NIC/TLS traffic. Online repair/verifier remains disabled in the initial product.

## Rendering metadata (development Plan B)

`config.frozenConfiguration.answerRendering` accepts `model-guided-extractive` or `source-grounded-generation`; other/missing values are recorded as null. Root must bind this declaration to the deployed runtime configuration receipt (generation uses `DEMO_GROUNDED_RENDERING=source-grounded-generation`). `outcomes.extractive`, `outcomes.generated`, and `outcomes.renderingUnknown` are distinct declaration counts, not semantic-quality or successful-generation scores. Every sample retains `renderingProvenance: frozen-configuration-not-semantic-classification`. Actual inference counters and independent F/C/U/Q3 review remain separate; declaring generation cannot establish correctness or real inference. These metadata changes do not enable runtime generation or alter prompts.

## Hybrid rendering configuration evidence

Optional `renderingConfiguration:{"edge":"model-guided-extractive","core":"source-grounded-generation"}` must match in the public frozen manifest and private `frozenConfiguration`. Each value is one of those two modes or null; missing legacy values remain null. Malformed declarations or configuration/sample binding mismatches fail validation. This is configuration evidence, not per-call observation; matching primary/backup Edge replicas requires independent deployment configuration receipts. Never infer Edge mode from the final answer.

`answerRendering` and generated/extractive outcome counts retain their **final answer only** meaning; an explicit Core declaration must agree with `answerRendering`. Samples, report summary and sanitized monitor projection expose the separate Edge/Core declaration without promoting quality, semantic correctness or overall completion.
